## Product findings

1. **Declared roles disagree with seeded grants for `move_execute` and `putaway_suggest_location`.** `putaway_rpc.rs:42` and `move_command_rpc.rs:26` say `roles = [Admin, Manager]`. The baseline seed grants the same methods to OPERATOR and SUPERVISOR (`sql/wms-app/migrations/001_baseline.sql:19882,19886,19981,19987`), and the dev seed relies on it (`sql/dev_only/install-db/900-dev-seed.sql:52`). RF operators work only because of the seed row. The declaration is the thing the auto-seeder and the permission catalogue read (`crates/services/app-server/src/web/rpcs/catalog.rs:430`), so it is misleading. Also, the same two methods are the only ones an RF operator needs, yet `putaway_release_reservation` (`putaway_rpc.rs:44`) is Admin/Manager only while the RF putaway screen calls it (`sql/rf-screens/093_uc_putaway.sql:335`). Baseline grants it to OPERATOR (`001_baseline.sql:19885`), so it works, but only by the seed.
2. **Packing discrepancy has no way to be settled in code.** The report writes an open, blocking `packing_exception` (`exception_report.rs`), and the screen promises "the order waits for recovery" (`sql/rf-screens/103_uc_pack_verify.sql:260`). The only packing commands present are open work, close, void, reopen and report (`crates/libs/wms-outbound/src/packing/commands/`). Nothing sets an exception to a closed status (`PackingExceptionStatus::` is used nowhere outside the model). The comment in `exception_report.rs:10-11` refers to a later slice (E). Until it exists, a reported order cannot become Packed.
3. **A reported box stays in the pack queue.** The unit stays `Pending` (`outbound_flow_unit.rs` `station_queue`, `advance.rs:45-60`), so the box shows again under Waiting and can be scanned and closed. Close is blocked from marking the order Packed only through `judge_packed`. The PACK04 header comment says nothing about taking the unit out of the queue. If the product intent is "put the box aside", the queue should hide it.
4. **Wrong-password text is worded by the terminal, not by the server:** `Invalid username or password` (`clients/rf-go/internal/app/model.go:5180`). This closes the "exact text of a wrong-password message" block in `01-login-and-warehouse.md` (not in my scope; `00-README.md:58` already lists the text).
5. **Wording nit in the file header of `clients/rf-go/internal/app/errors.go:3-6`:** it names a source file `error.rs` under `rfmanagement/receipt/services/` in the crate `wms-business-logic` that no longer exists (the `rfmanagement/` folder was renamed to `service/` on 2026-07-30 per `.claude/CLAUDE.md`).
