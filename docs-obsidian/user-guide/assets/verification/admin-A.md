## Product findings

F1. Bootstrap administrator probably cannot sign in. `libs/wms-lib-auth/src/authorization/bootstrap.rs:109-122` writes a raw Argon2 PHC string (no `#02#` style prefix) and an empty salt. `libs/wms-lib-auth/src/pwd/mod.rs:94-104` (`PwdParts::from_str`) needs `^#(\w+)#(.*)`. `wms-lib-web/src/handlers/handlers_login.rs:112-126` then fails with `LoginFailPwdNotMatching`. Needs a run to confirm. No test covers hash-then-login for this command (`bootstrap.rs` tests at `:170+` test only config).

F2. No server-side password rule. `libs/wms-lib-core/src/model/user.rs:479-515` and `:675-700`; RPCs `create_user` / `update_user`. An empty password is stored on create. The only check is on sign-in (6 characters), so an account made with a short password can never sign in.

F3. Wrong message on sign-in. `services/web-ui-server/src/routes/http_params.rs:26`: rule is `min = 6`, text says 8.

F4. `must_rotate_password` is dead. It is written (`bootstrap.rs:122`) and in the schema (`wms-enterprise/migrations/001_baseline.sql:216`), but no reader exists. The CLI message `services/app-server/src/cli.rs:82` and the log line `bootstrap.rs:148` tell the operator to rotate "on first login", which nothing prompts. `failed_login_attempts` is audit only (`user.rs:778-800`).

F5. Duplicate-key and generator errors hide the cause. `libs/wms-lib-web/src/error.rs:393-398` returns `Record already exists` for every unique violation that has no model-level resolver, with no constraint name. Generated locations (`gen_locs`) fail as a whole when one code exists, and the user is not told which code.

F6. Stale design note: `docs-obsidian/putaway_policy/README.md:53,88` says `putawayzone_lot_commingle` has no reader. It has one since `libs/wms-inventory/src/inventory_service.rs:1537-1553`.

F7. Inconsistent check digit: `create_loc` computes it (`location_rpc.rs:42-44`), `gen_locs` does not (`:113-122`), although both are described by the setting `CHECK_DIGIT_ENABLED` ("new locations", `wms-app/migrations/001_baseline.sql:9947`).

F8. Dead enterprise menu item `Dashboard` (`ent_dashboard`, `wms-meta-ui/migrations/001_baseline.sql:21044`): no form, no event. Same class as `Warehouses` and `Owners`.

F9. Stale comment: `services/web-ui-server/src/services/snapshot/impersonation.rs:123-125` (and `:1468`) says the server logout does not touch the session. `routes/login_handler.rs:95-101` does `session.flush()`.

F10. Throttle is per process only (`login_throttle.rs` header). With several app-server copies the allowed rate multiplies. A stated limit, not a bug.

F11. Other guide files may repeat the wrong registry form code. Not checked here: `04-owners-sku-uom-pack-hierarchy.md` (`handling_unit_registry_shell_form`). Owner of that file should check against `080_handling_unit_screens.sql:314,528-570`.
