## Product findings

- `crates/services/web-ui-server/src/meta/surface_census.rs:158`: the screen `printer_assignments_list_form` has no door. Admins cannot manage printer assignments in the UI. Same for four other forms listed there.
- `crates/services/app-server/src/web/rpcs/putawayzone_rpc.rs:55-56` and `crates/libs/wms-lib-core/src/model/printer_assignments.rs:170-211`: the zone fields `Default Label Printer`, `Default Report Printer`, `Auto Print Addr Label` and `Auto Print Carton Label` are shown on the zone form but no printing code reads them. They look like they work.
- `crates/libs/wms-lib-core/src/model/reports/printer_configuration.rs:27-28`: `zone_code` and `is_default` of a printer are stored and never used by the printer lookup.
- `crates/services/app-server/src/web/rpcs/receipt_commands_rpc.rs`: `receipt_set_damage_disposition`, `receipt_write_off_damage`, `receipt_move_damage_to_rtv` have no web button and no RF screen. A damage record can stay pending, and a receipt with pending damage cannot close (code 77).
- `crates/libs/wms-lib-sql/sql/wms-app/migrations/001_baseline.sql:2067` with the receipt line form: `receipt_detail.pack_id` is `NOT NULL`, but the form does not mark `Pack` as required. The operator gets a database error. **Fixed (F-20):** `ReceiptDetailBmc::create` takes the SKU's pack when none is given.
- `crates/services/web-ui-server/src/components/pages/integration_platform.rs:26`, `crates/services/integration-platform/src/server.rs:197`, `crates/services/integration-platform/src/middleware.rs:35-60`: the IPaaS frame uses a fixed address `http://localhost:8085`, the CORS list is fixed to `localhost` origins, and the UI sends no `X-Api-Key` while CORS does not allow it. With `IP_API_KEY` set, the embedded IPaaS cannot log in. It only works in dev mode.
- `crates/libs/wms-lib-sql/sql/wms-app/migrations/001_baseline.sql` (`owner_config.default_replenishment_policy_id`, `default_lot_policy_id`; `app-server/.../owner_config_rpc.rs:73-75`): both defaults are stored and shown but no Rust code reads them.
- `crates/services/web-ui-server/src/components/pages/reports_iframe.rs:852-865`: the report and label designer right is the Studio-admin right. There is no separate right for editing reports (the code comment says it is temporary). Also `reports=["*"]` lets every user run every report (`reports_iframe.rs:798-807`).
- `crates/libs/wms-outbound/src/service/order/close.rs:1-18`: the code comment says a shipment order can close only when all lines are cancelled, because nothing ships yet. Check whether the comment is current.
- `docs-obsidian/domain/pack-hierarchy.md:26,52`: the design note still describes `parent_pack_item_id`. The database uses `child_pack_item_id`.
- `crates/services/web-ui-server/src/components/pages/dashboard/dock.rs` and `labour.rs`: the dock schedule and labour panels have no data source. They show demo figures or say so.
