## Product findings

1. **Return location default does not exist in the standard seed.** Screens default To Loc to `RETURNS` (`rf-screens/050_uc_rtn_declarative.sql:205`, `055_uc_rtn_multi_line.sql:331`). The seed creates `RETURN` (`wms-app/migrations/001_baseline.sql:8379`). A default install refuses the default value with "Invalid location RETURNS". Fix the screen default or the seed. **Fixed (F-26):** `RCRTN01LINE` / `RCRTN02LINE` rev 2 default to `RETURN` (rf-screens 120).
2. **Receipt Closed prompt lies.** It says "Press Enter to return to main menu" (`rf-screens/020_uc_asn_declarative.sql:922-923`) but `onEnter` is `pop_to RCM` (the Receiving menu). **Fixed (F-27):** `RCASN03DONE` rev 2 says "…to the Receiving menu" (rf-screens 120).
3. **"Receipt without LPN is allowed only via supervisor override" is misleading.** The code table lets the operator acknowledge it alone (`libs/wms-shared/src/validation_codes.rs:559-570`, `ReceiptWithoutLpn => None`); the doc comment in `libs/wms-inbound/src/service/receipt/validation/validation_pipeline.rs:86-87` also says "supervisor cap". Message, comment and gate disagree. **Fixed (F-28):** the refusal says "This receive has no LPN" and the terminal asks; the comment follows the gate (meta-ui 150).
4. **Permission mismatch, force-close picker. Fixed (F-25/B1-18).** `force_close_episode` and `list_force_close_candidates` share the Admin/Manager/Supervisor declaration. Enterprise migration 020 grants SUPERVISOR the list on existing databases, and RF hides the menu entry from Operator and Viewer.
5. **Declared defaults disagree with baseline grants.** `receipt_receive_against_asn` is Admin/Manager in `receipt_commands_rpc.rs:40-43`, `move_execute` is Admin/Manager in `move_command_rpc.rs:26`, `putaway_suggest_location` and `putaway_release_reservation` are Admin/Manager in `putaway_rpc.rs:42,44`. The baseline migration grants all of them to OPERATOR (role 1002, `001_baseline.sql` around lines 19838-19990). Migration 047's header says the router lists "now stand" with the migration, which is true for blind/return/close but not for these. Result depends on whether a database came from the baseline or from the seeder alone.
6. **Operator-facing text with internal wording.** A Russian sentence inside the English message at `receive_case_level_line.rs:366` ("у строки приёмки {} нет упаковки ..."). Messages with internal ids and field names reach the terminal: `receive_case_level_line.rs:960` ("receipt_detail_case {id} flipped by a concurrent scan; retry"), `cancel_planned_case.rs:134`, `replace_pallet.rs:114` (`old_pallet_lpn`), `:229`. **Fixed (F-29):** the pallet-replacement refusals and the concurrent-scan error are in the operator's words, the last one now a typed refusal with Russian (meta-ui 150).
7. **"No permission: {function}" shows a server command name** (for example `receipt_close`, `force_close_episode`), not a menu name (`clients/rf-go/internal/app/submit_context.go:296`). Operators cannot map it to a screen. **Fixed (F-30):** rf-go says "No permission: {screen} ({function})".
8. **Dead screen.** `RCCASE_LIST` is seeded and granted (`wms-app/migrations/047_...sql:29`) but no screen navigates to it. **Fixed (F-31):** removed (owner, 2026-10-13) — `F2` on RCCASE02 already lists the unreceived cases; rf-screens 121 deletes the seeded screen.
9. **Force-Close item was shown to every user. Fixed (B1-18).** rf-go carries the selected warehouse role in session globals, and every seeded Receiving/Picking menu revision gates the entry to Admin, Manager and Supervisor.
